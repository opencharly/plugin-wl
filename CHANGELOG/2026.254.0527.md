# 2026.254.0527 — wl: land artifacts via sdk.LandArtifact (R3)

## Summary

Migrate the wl plugin's artifact placement off the hand-rolled `ex.GetFile` + `os.WriteFile(0o644)` dance (`candy/plugin-wl/methods.go` screenshot path and the optional ocr capture leg) onto the shared **`sdk.LandArtifact(ctx, ex, venuePath, artifact, op)`** entry point (sdk v0.2026254.439, sdk#249) — R3: one implementation per behavior; the executor IS the placement abstraction (venue pull when `ex != nil && venuePath != ""`, host no-op otherwise, validation always runs via `RunArtifactValidators`).

- `methods.go`: `wlScreenshot` and `wlOcr` now take the `*spec.Op` and call `sdk.LandArtifact` for the venue→host pull + write + the step's artifact validators. The ocr capture leg keeps its best-effort warning-only contract (a failed land or a failed declared artifact validator remains a warning; the verdict-time artifact gate in `provider.go` still fails the step on a broken declared assertion).
- `go.mod`/`go.sum`: sdk `v0.2026243.1202` → `v0.2026254.439` (spec → `v0.2026250.2036` via `go mod tidy`, the new sdk's own requirement).
- Comments in `methods.go` / `provider.go` updated to the LandArtifact semantics.
