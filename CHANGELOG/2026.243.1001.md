# 2026.243.1001 — fix(wl): exec and clipboard set never returned for commands that do not exit

## Summary
wl: exec exists to start GUI apps - things that map a window and keep running. It could
not report one successfully. Measured on a live Hyprland guest, in the omarchy desktop bed:

    FAIL  the terminal launches and maps a window
          wl: exec: launching "foot": rpc error: code = DeadlineExceeded

    PASS  the terminal window is present
    PASS  closing the terminal removes its window

The app launched, mapped its window, and closed on request. Only the verb that started it
reported failure - a false FAIL for correct behaviour, which is the worst shape a check
verb can take: it teaches the author to widen the timeout or delete the step.

## Root cause

    cmd := fmt.Sprintf("export DISPLAY=:0; %s &", in.Command)

The comment above that line said "Background the process so it doesn't block". The
trailing & backgrounds the JOB, but the child INHERITS stdout and stderr, so the pipe
wlCapture reads never reaches EOF. The capture blocks until the child exits - which for a
terminal or an editor is never - and the deadline fires.

Backgrounding is not detaching. The fix redirects all three streams so the pipe closes
immediately, and setsid detaches the child from the session so it outlives the shell that
launched it. That is the same pair of things upstream omarchy's own launch_app does:

    setsid -f bash -c "$1" >/dev/null 2>&1

stdin is closed too - an app inheriting the capture's stdin can block on a read of its
own. DISPLAY=:0 stays for XWayland apps, and the command stays unquoted so multi-argument
launches like "chromium --new-window" keep working.

The line moves into wlExecCommand so it can be pinned by a test; nothing else changes.

### A second instance of the same defect: `clipboard set`

`wl-copy` also stays alive — it must, to own the Wayland selection — and its streams were
inherited too, so `wl: clipboard set` blocked identically on a copy that had succeeded:

```
FAIL  seed the clipboard with a known token
      verb "wl": rpc error: code = DeadlineExceeded
```

Same cause, same fix, same PR. Shipping only the exec half would have left the pattern to be
rediscovered by the next author who used the verb.
