# 2026.258.1844 — fix(wl): aim Hyprland window actions by the table selector, and fail on a silent dispatch

## Summary

Four measured defects in the Hyprland window verbs (`wl: focus|close|fullscreen|minimize`),
each reproduced live on Hyprland 0.56.2 — **4 substantive commits** (plus body-only
`docs: re-trigger validation` empties that the squash collapses):

1. `fix(wl): aim Hyprland window actions by the table selector, and fail on a silent dispatch`
2. `test(wl): unit-test the dispatch stdout classifier as a pure function`
3. `fix(wl): normalize the focus selector too, so all four window verbs are uniform`
4. `test(wl): assert the focus arm's REAL expression builder`

### 1. The action was aimed by a preceding focus, not by a selector

`hyprctlFocusThen` was built on the reading that `hl.dsp.window.close(<sel>)` ignores its
selector. That is true of the POSITIONAL form — but the **TABLE** form
`hl.dsp.window.close({window=<sel>})` HONORS it (verified live: closes only the named window
while the focused one survives). Focus-then-act is also unusable on a headless bed, where
`activewindow` is null, so the bare action hits nothing. The window verbs now carry the
selector in the action table (`hyprctlWindowAction` → `hyprWindowActionExpr`).

### 2. `hyprctl dispatch` failures were invisible

`hyprctl` is exit-code-useless for dispatches: it prints `error:`/`warning:` to STDOUT and
exits 0 (measured: `hl.focus: window not found` → `echo $?` = 0). `wlSilent` checked only the
exit status, so an unresolvable selector was reported as SUCCESS and the action hit whatever
was focused (or nothing) — the false-success shape that makes `wl: close` claim
`Closed window matching "X"` for a window still open. The new `hyprctlDispatchChecked` fails
unless stdout is exactly `ok`, and the classification is the pure, unit-tested
`hyprDispatchOutcome`.

### 3. Cross-backend divergence: bare targets

`wlrctl` (sway/labwc) matches a BARE target as the app id (`wlrctl toplevel close foot`), so
every bed authors `target: foot`. A bare string matches NOTHING in a Hyprland action table, so
the same bed silently failed ONLY on Hyprland. New `hyprSelector` normalizes a bare target to
`class:<target>` and passes an explicit selector (`class:`, `initialtitle:`, `address:`, …)
through unchanged.

### 4. `wl: focus` did not normalize (the divergence survived on one verb)

The normalization above was applied to the window ACTIONS (`hyprctlWindowAction`) but `wlFocus`
still dispatched `hl.dsp.focus({window = <raw target>})` — so a bare `target: foot` matched
nothing on Hyprland for **focus alone**, while close/fullscreen/minimize worked. Worse, once
focus moved to the CHECKED dispatch, that unmatched bare target became a HARD ERROR on Hyprland
where it had silently no-op'd before. Commit 3 routes focus's selector through `hyprSelector`
too, so all four verbs are uniform — and `TestHyprFocusSelectorIsNormalized` asserts on
`hyprFocusExpr`, the builder `wlFocus` actually DISPATCHES, so it fails if the focus arm stops
normalizing (mutation-verified: reverting `hyprFocusExpr` to a raw target fails it).

`hyprctlFocusThen`/`hyprWindowActionExprs`/`hyprctlDispatch` are deleted (R5 — no legacy path
survives); only `hyprctlDispatchChecked` remains.
