# 2026.243.1212 — feat(wl): expose artifact_contains_text, the OCR assertion

## Summary
sdk v0.2026243.1202 added artifact_contains_text to the shared artifact-validator pipeline
every artifact-producing verb already calls. This declares the field in this plugin's own
schema so a wl: screenshot step can author it, and repins the sdk so the validator is
actually there to run.

    schema   artifact_contains_text?: string
    sdk      v0.2026234.347 -> v0.2026243.1202
    spec     v0.2026232.520 -> v0.2026243.707   (transitive)

It is the assertion that separates a surface MAPPED from a surface RENDERED. hypr-layers
can report a layer present, correctly sized and on screen while it draws nothing, and
artifact_not_uniform passes on any wallpaper. Upstream omarchy's acceptance suites use
this shape for the checks that matter most - that the weather panel really rendered its
location, that a menu shows its entries, that a notification body is on screen.

## The params struct is GENERATED, and was generated

No hand-edit. There is no Taskfile in this repo, so the documented pipeline was replicated:
spec's pinned cue binary via its bootstrap-cue task, the schema wrapped as the header
comment describes (package params plus the go attribute), cue exp gengotypes, then spec's
schemagen retag mode for the yaml tags.

Proof it is the real generator output rather than a transcription: regenerating reproduces
the committed file EXACTLY plus the new field - 11 insertions, 1 deletion, the deletion
being a comment line that wrapped.

## The wire name is pinned by a test, because a mismatch is SILENT

The sdk reads this modifier out of the desugared plugin-input MAP by string key. Nothing
type-checks that lookup against this schema; they meet only at runtime, through a map. A
rename or typo on either side does not fail to compile and does not error - the sdk finds
no key, reads the empty string, and SKIPS the validator. The step passes while asserting
nothing.

That is the silent-skip shape this repo has met before, and it is the worst possible
outcome for an OCR assertion whose entire purpose is catching a surface that mapped
without rendering. So a test round-trips WlInput and asserts the serialised key is exactly
what the sdk looks up, and a second asserts the served schema declares the field at all.

## How tested

    go test -count=1 ./...
    ok  github.com/opencharly/plugin-wl/candy/plugin-wl  0.005s

NEGATIVE-CONTROLLED. With the wire name changed to artifact_contains_txt the round-trip

    WlInput does not serialise a "artifact_contains_text" key, so the sdk validator would
    read "" and SKIP the assertion silently
