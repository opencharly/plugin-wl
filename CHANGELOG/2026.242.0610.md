# 2026.242.0610 — fix(hyprland): aim the window dispatchers — they all act on the ACTIVE window

## Summary

**Every `hl.dsp.window.*` dispatcher in Hyprland operates on the ACTIVE window.** Some of them
accept a selector argument and then silently ignore it — which is the dangerous shape, because the
call returns `ok` and the action reports success against a window it never touched.

Measured on 0.56.2 with four `foot` windows mapped:

```
focused C, then hl.dsp.window.close("initialtitle:cstream-d")   →  C died,  D survived
focused A, then hl.dsp.window.move({selector = "…-b", …})       →  A moved, B stayed
```

So this is a **bug fix first**: `wl: close` on Hyprland — ported in the B3 cutover with the comment
*"hl.dsp.window.close accepts a window selector"* — has been closing whatever was focused, and
`wl: fullscreen` never passed a target at all. Both now focus the named window first, behind one
documented helper (`hyprctlFocusThen`).

**And it unblocks the two verbs B8 recorded as unsupported.** The earlier finding — that
`hl.dsp.focus` *"takes a direction table, not a window selector"* — was half right. It takes a
**table**, and that table accepts **either** `direction` **or** `window`; only `direction` had been
tried:

```
{direction = "left"}          → HL.Dispatcher      (the known form)
{window = "initialtitle:…"}   → HL.Dispatcher      ← accepted; this is the answer
{selector=…} {address=…} {target=…}  → nil, silently
```

| verb | before | now |
|---|---|---|
| `wl: focus` | error: unsupported on Hyprland | `hl.dsp.focus({window = <selector>})` |
| `wl: minimize` | error: unsupported on Hyprland | focus, then `hl.dsp.window.move({workspace = "special:minimized"})` |
| `wl: close` | **closed the focused window** | focus the named one, then `hl.dsp.window.close()` |
| `wl: fullscreen` | **fullscreened the focused window** | focus the named one, then `hl.dsp.window.fullscreen(1)` |

Hyprland has no minimize *state*; a named special workspace is the compositor's own idiom for it,
so that mapping is the feature rather than a substitute for a missing one.

## Change classification

**Change class:** plugin Go — **four** verb case-blocks rewritten, not three (the earlier count was
wrong and is corrected here):

| item | what |
|---|---|
| `wlFocus` | rewritten from an unconditional error into a real implementation |
| `wlClose`, `wlFullscreen`, `wlMinimize` | rewritten to route through `hyprctlFocusThen` (`wlMinimize` also from an error) |
| `hyprctlFocusThen` + `hyprWindowActionExprs` | two new helpers — the second split out so its output is assertable without a compositor |
| `errHyprlandLuaDispatcher` | deleted (no longer reachable) |
| `hyprMinimizeWorkspace` | new named constant |
| `hyprland_dispatch_test.go` | new in-tree test file |
| `charly.yml` | candy `version:` bump |

No schema, no generated code, no new dependency.

**Verification gate:** a `disposable: true` bed with a live nested Hyprland and **mapped windows**
— the gate B8 specified — asserting observable state changes rather than absence of error.

**Breaking change + rollback:** `wl: focus` and `wl: minimize` stop erroring on Hyprland and start
working; `wl: close` and `wl: fullscreen` change which window they act on — **to the correct one**.
A consumer relying on the old close behaviour was relying on a bug. Rollback is a plain revert.

**3. Every gate asserts OBSERVABLE STATE, and each is built so the bug it guards would fail it.**

- *focus* is asserted **both ways** (A then B). A single direction passes on a compositor that
  focuses arbitrarily; the round trip does not.
- *close* asserts **two** things — the named window is gone **and** the focused one survived.
  "The target is gone" alone passes on the pre-fix bug whenever the target happened to be focused;
  the survivor is what catches it. This check fails against `main`.
- *minimize* asserts the window is **on** `special:minimized`, not merely that the workspace
  exists. The workspace is created on first use, so its existence alone is satisfiable by any
  earlier minimize — the per-window assertion is the discriminating half.

**4. The selector form matters, and the obvious one does not work.**
`title:` selectors are useless for automation here: a terminal rewrites its title within a second
of mapping, so all four `foot` windows report `@host:~` and `hl.focus: window not found` is the
result. The gate uses `initialtitle:`, which is stable; `address:` from `hl.get_windows()` is the
alternative when one is to hand.

**5. One tooling note that made this findable.** `hyprctl eval` answers `ok` for *every*
expression — `return 1+1` included — so it cannot be used to read a value, and an introspection
attempt through it looks like uniform success. `hyprctl repl <code>` is the one that prints the
result. The whole namespace enumeration above depends on that distinction.
