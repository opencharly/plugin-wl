# 2026.243.1401 — docs(skill): the artifact validators, OCR, and what exec does not do

## Summary
The wl skill documented screenshots but not what to ASSERT about one, and described exec as
"launch application in container" without the two properties that decide whether it is the
right verb. Both gaps produced real defects this session.

## The artifact validators, as a ladder

A new section lists all five and explains that they are not alternatives: min_bytes passes on
a blank PNG, not_uniform passes on a wallpaper with every panel missing, and only
artifact_contains_text fails unless the pixels actually spell something.

That distinction is sharpest for layer-shell surfaces, so the section pairs the two verbs
explicitly: hypr-layers can report a surface present, correctly sized and on screen while it
renders nothing, and a bed asserting presence alone will pass a shell that came up broken.

artifact_contains_text gets its own subsection, because it is the one validator with a HOST
dependency. The validators run host-side on the pulled artifact, so tesseract and a language
pack must be where charly runs, not in the image under test - and charly declares both as
optional package dependencies. It also records the property that cost real debugging time:
with no language data tesseract writes to stderr and exits with empty stdout, indistinguishable
from a genuine no-match, so the validator checks stderr first and names the cause.

## What exec does not do

exec detaches and redirects to /dev/null - right for a GUI app that keeps running, wrong for a
fast state change. The skill now says so, with both consequences: it returns before the command
has done anything, and it discards the exit status, so a launch that fails silently looks like
one that succeeded. For a short command whose exit status IS the assertion, use command.

That is not hypothetical. A bed used wl exec for a bar toggle; the toggle silently did not land
and the failure surfaced two steps later against unrelated state. The mechanical reason for the
redirect is recorded too - an inherited stdout keeps the capture pipe open, so the verb used to
block for its whole deadline on a process that never exits, reporting DeadlineExceeded while the
next step found the window mapped.
