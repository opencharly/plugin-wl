# 2026.244.0851 — fix(wl): wake a DPMS-off output before the screenshot

## Summary

grim hangs forever waiting for a frame from a compositor output that went into DPMS off (idle screensaver) — the screenshot probe then hits the never-hang bound and fails after minutes. RCA: a VM left running long enough for the display to sleep (the compositor log shows 'Disabling output <name>', hyprctl reports dpmsStatus: false); the same grim on an enabled output captures in milliseconds.

Fix: `wakeOutput` re-enables the output before the grim capture — compositor-aware: Hyprland uses the Lua dispatcher (`hl.dsp.dpms({action = "enable"})` — the legacy `hyprctl dispatch dpms on` argv is rejected under the Lua config manager), wlroots uses `wlr-randr`. The command construction is extracted into the pure `wakeOutputCmd` for testability.
